## 3. Price sync service

- [x] 3.1 Create `subscriptions/services/plan_sync.py` with `ensure_stripe_price(plan, user=None) -> BillingPlan`. The function is idempotent: if `plan.stripe_price_id` is set AND the (amount, currency, interval) tuple matches the values on the plan, return the plan unchanged. Otherwise: (a) call `stripe_client.get_or_create_product(name=plan.name, existing_id=plan.stripe_product_id)` and store `product.id` on the plan; (b) call `stripe_client.create_price(product_id=plan.stripe_product_id, amount_decimal=plan.amount, currency=plan.currency, interval=plan.interval)` and remember the new `price.id`; (c) call `stripe_client.set_product_default_price(product_id, new_price_id)` to repoint `default_price` before archiving (Stripe blocks archiving the default price); (d) if `plan.stripe_price_id` is non-empty, call `stripe_client.archive_price(plan.stripe_price_id)`; (e) create a `BillingPlanPriceHistory` row capturing `old_stripe_price_id=old`, `new_stripe_price_id=new`, `amount`, `currency`, `interval`, `old_price_archived=(old != "")`, `changed_by=user`; (f) set `plan.stripe_price_id = new`, `plan.stripe_product_id = product.id`, `plan.last_synced_stripe_at = timezone.now()`; (g) `plan.save(update_fields=["stripe_product_id", "stripe_price_id", "last_synced_stripe_at"])` (no `updated_at` — SingletonModel has no timestamp). Return the plan. **Do NOT** call `plan.save()` for the editable fields — that's the admin's job, after this function returns successfully.
- [x] 3.2 `ensure_stripe_price` MUST re-raise any `stripe.error.StripeError` so the admin's `save_model` can surface the failure to the operator. It MUST NOT swallow exceptions or partially commit.
