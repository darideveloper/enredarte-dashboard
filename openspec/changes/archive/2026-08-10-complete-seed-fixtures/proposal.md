## Why

After `base_loaddata` + `seed_loaddata` on a fresh database, six business tables are always empty: `ArtCurator`, `ArtCuratorTranslation`, `Gallery`, `GalleryTranslation`, `ArtworkGallery`, and `ArtworkImage`. There is no fixture data at all for curators, galleries, gallery↔artwork links, or artwork images, so the catalog is only half-populated and every admin module for those models opens empty.

## What Changes

- Add missing **seed fixtures** so every business table has rows after a manual `seed_loaddata` run:
  - `ArtCurator` + `ArtCuratorTranslation` (2 curators, bilingual bios).
  - `Gallery` + `GalleryTranslation` (2 galleries referencing the seeded curators, bilingual name + description).
  - `ArtworkGallery` links across the existing seeded artworks and the new galleries (each row carries a unique `slug`; slugs are also auto-generated by the model's `save()` if omitted, but explicit values keep the fixture deterministic).
  - `ArtworkImage` (1 image per seeded artwork, `is_primary` on it).
- **Renumber seed fixture filenames with numeric prefixes** (`00_`, `01_`, …) so the loader's alphabetical sort resolves dependencies: `Gallery` must load before `ArtworkGallery`, which the current alphabetical order would break (fail-soft would silently drop the rows).
- **Seed media sync**: commit small placeholder images under `artworks/fixtures/artworks/seed/images/` (`media/` is gitignored) and write them into the configured default storage (local `MEDIA_ROOT` or S3 bucket) from `seed_loaddata`, so artwork image rows reference readable files in every environment.
- **No lifecycle change**: `base_loaddata` stays auto-loaded in `start.sh`; `seed_loaddata` stays a manual, one-time command run per environment (prod and dev). Admin/auth tables (`User`, `Group`, `Token`) remain out of scope.
- Update `docs/django-fixtures.md` seed-file inventory and the `seed_loaddata` example to match the new ordering convention.

## Capabilities

### New Capabilities
- `seed-content-completeness`: Guarantees every business model has seed data — curators, galleries, artwork↔gallery links, and artwork images — so no business table is empty after a manual `seed_loaddata` run.

### Modified Capabilities
- `fixture-loading`: Adds deterministic cross-fixture load ordering via numeric-prefixed seed filenames and a seed-media copy step, so dependency-dependent seed fixtures (e.g. `ArtworkGallery` after `Gallery`) load correctly on first run.

## Impact

- **Fixtures (new)**: `artworks/fixtures/artworks/seed/00_ArtCurator.json`, `01_ArtCuratorTranslation.json`, `06_Gallery.json`, `07_GalleryTranslation.json`, `08_ArtworkGallery.json`, `09_ArtworkImage.json`.
- **Fixtures (renamed)**: existing `Artist.json`, `ArtistSocialLink.json`, `ArtistTranslation.json`, `Artwork.json`, `ArtworkTranslation.json` get numeric prefixes.
- **Images**: 6 committed placeholders under `artworks/fixtures/artworks/seed/images/artworks/` (`obra-1.jpg` … `obra-6.jpg`, one per seeded artwork).
- **Command**: `core/management/commands/seed_loaddata.py` gains a small media-sync loop (no behavior change to fixture discovery/loading).
- **Tests**: `artworks/tests.py` seed scenarios still pass (they only assert row counts); new tests assert `Gallery`/`ArtCurator`/`ArtworkGallery`/`ArtworkImage` are populated by `seed_loaddata` and that a re-run keeps counts.
- **Docs**: `docs/django-fixtures.md`.
- **Note**: seed images are written through the configured default storage (`FileSystemStorage` → `MEDIA_ROOT`, S3 → bucket) at seed time, so every environment gets readable image files.
