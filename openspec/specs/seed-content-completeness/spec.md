## Requirements
### Requirement: Seed data covers every business model
The system SHALL ship seed fixtures so that every business model table has at least one row after `base_loaddata` followed by `seed_loaddata` runs against a fresh database. The seed set SHALL include curators, galleries, artwork↔gallery links, and artwork images in addition to the existing artists, social links, and artworks.

#### Scenario: Fresh seed run populates all business tables
- **WHEN** `seed_loaddata` runs on a fresh database that already ran `base_loaddata`
- **THEN** the `ArtCurator`, `ArtCuratorTranslation`, `Gallery`, `GalleryTranslation`, `ArtworkGallery`, and `ArtworkImage` tables each contain at least one row, and no business model table remains empty.

#### Scenario: Seed translations are bilingual
- **WHEN** a seeded `ArtCurator` or `Gallery` row is inspected
- **THEN** it has both an `es` and an `en` translation row referencing it.

#### Scenario: Gallery links reference seeded rows
- **WHEN** an `ArtworkGallery` seed row is inspected
- **THEN** its `artwork` references an existing seeded `Artwork` and its `gallery` references an existing seeded `Gallery`, and it carries a unique `slug` (supplied by the fixture or auto-generated by `ArtworkGallery.save()`).

#### Scenario: Artwork images reference a readable file
- **WHEN** an `ArtworkImage` seed row is loaded
- **THEN** the referenced image file exists in the configured default storage (written from the committed seed images) and exactly one seeded image per artwork is marked `is_primary`.

#### Scenario: Idempotent on re-run
- **WHEN** `seed_loaddata` runs a second time against the same populated database
- **THEN** rows are matched by their explicit PKs and updated in place, and no table's row count increases.

#### Scenario: Admin/auth tables stay out of scope
- **WHEN** the seed fixtures are inspected
- **THEN** they contain no `auth.User`, `auth.Group`, or `authtoken.Token` rows.
